# 角色与权限说明（系统角色 + 项目角色）

平台采用"**两层角色模型**"：系统角色决定平台级权限，项目角色决定项目内协作权限，两者组合生效。

## 一、系统角色（平台级）

| 系统角色         | 英文标识                | 说明                                                                 |
| ---------------- | ----------------------- | -------------------------------------------------------------------- |
| 学生             | `student`               | 普通学生账号，默认参与项目协作、提交申请与进展、发起会议等。         |
| 教授 / 教师      | `professor`             | 指导者视角，可点评项目、审核进度、查看全局看板（按配置授权）。       |
| 实验室业务管理员 | `lab_admin`             | 负责物资类别、审批流程、成员纳入、知识库维护等实验室日常业务治理。   |
| 平台管理员       | `admin` / `super_admin` | 平台治理角色，拥有成员目录、角色模板、审计日志、系统健康等全量能力。 |

## 二、项目角色（项目内）

每个项目拥有独立的项目成员与项目角色。同一用户在不同项目中可以拥有不同的项目角色。

| 项目角色    | 英文标识   | 说明                                                                      |
| ----------- | ---------- | ------------------------------------------------------------------------- |
| 项目负责人  | `owner`    | 项目创建者 / 总负责人，负责推进项目、分配任务、管理资料、提交立项与汇报。 |
| 组长 / 骨干 | `leader`   | 按负责人授权协助管理任务与成员。                                          |
| 普通成员    | `member`   | 查看自己的任务、提交进展、上传资料、填写问题、参与会议。                  |
| 教师 / 导师 | `advisor`  | 指导、点评、审核，通常不负责具体任务分配。                                |
| 观察者      | `observer` | 只读查看，用于评审、跨组交流等场景。                                      |

## 三、项目内权限矩阵（核心操作）

| 操作                            | owner  | leader | member | advisor | 管理员 |
| ------------------------------- | ------ | ------ | ------ | ------- | ------ |
| 查看项目                        | ✓      | ✓      | ✓      | ✓       | ✓      |
| 创建 / 分配任务                 | ✓      | 按授权 | ×      | ×       | ✓      |
| 更新自己的任务状态              | ✓      | ✓      | ✓      | ×       | ✓      |
| 提交进展 / 资料 / 问题          | ✓      | ✓      | ✓      | ×       | ✓      |
| 查看项目全部提交                | ✓      | ✓      | 受限   | ✓       | ✓      |
| 点评 / 退回 / 确认              | 按授权 | 按授权 | ×      | ✓       | ✓      |
| 修改项目基本信息                | ✓      | 按授权 | ×      | 按授权  | ✓      |
| 管理项目成员（增删 / 调整角色） | ×      | 按授权 | ×      | 按授权  | ✓      |
| 归档 / 关闭项目                 | ✓      | ×      | ×      | ×       | ✓      |

> 说明：
>
> - "按授权"：具体能力将在 v1.0 联调时按 leader / advisor 的独立权限设计补齐；当前代码已落地 owner / member / admin 基础校验。
> - "受限"：普通成员通常只能查看自己相关的提交明细，不可下钻查看其他成员的未公开资料（按项目设置决定）。

## 四、角色与 AI 助手的关系

- AI 助手**不会突破当前用户的权限**：例如 student 无法通过 AI 绕过审批直接通过耗材申请。
- AI 调用任何业务工具时，上下文都携带当前登录用户（actor），工具执行前会再次校验角色 / 权限。
- AI 助手的知识库管理（写文档 / 删除文档）建议仅对 `lab_admin` / `admin` / `professor` 开放，普通学生以"只读答疑"为主。

## 常见问题（框架）

| 问题                               | 建议答复（待业务具体实现后补全）                                                      |
| ---------------------------------- | ------------------------------------------------------------------------------------- |
| 如何成为项目负责人？               | 由管理员或有权限的教师在创建项目时指定，或在管理中心调整 owner。                      |
| 可以同时在多个项目拥有不同角色吗？ | 可以。项目角色是项目维度，互不影响。                                                  |
| 学生可以审批吗？                   | 平台级一般不允许；若某个具体项目授权给 leader（即使是学生身份），可按项目内授权执行。 |
| 忘记自己是什么角色？               | 可在"个人设置 / 成员目录 / 项目详情 - 成员与角色"中查看。                             |
