# 公共资料、项目资料、NAS 索引使用说明

## 三者定位对比

| 分类 | 归属 | 典型内容 | 可见范围 |
| --- | --- | --- | --- |
| 公共资料 | 平台级 | 全实验室通用 SOP、规章制度文档、模板、公告附件 | 所有登录成员 |
| 项目资料 | 项目级（project_id） | 立项书、任务说明、实验方案、分析结果、结项材料 | 仅项目成员 + 相关管理员 |
| NAS 索引 | 平台级 + 可关联项目 | 大文件、原始数据、测序、图像、备份的路径登记 | 按索引权限控制 |

## 公共资料使用建议

- **作为"标准 + 模板"仓库**：
  - SOP（标准操作流程）
  - 申请单模板、汇报模板、结项模板
  - 规章制度 PDF（安全、设备使用、保密等）
  - 对外合作 / 通知附件
- 写入权限：建议 lab_admin / admin / professor。
- 更新策略：重要 SOP 更新后，建议在 AI 知识库同步一份最新版本，便于答疑引用。

## 项目资料使用建议

- 作为"项目过程资产库"：
  - 立项材料、审批记录
  - 实验方案、分析脚本说明、图表
  - 会议纪要、周报月报草稿、结项草稿
- 建议子文件夹结构（示例，实际按组内约定）：
  - `01-立项/`
  - `02-方案/`
  - `03-原始数据索引/`（放 NAS 索引链接，不放大文件）
  - `04-分析结果/`
  - `05-汇报/`
  - `06-结项/`

## NAS 索引使用说明

### 为什么要有"索引"而不直接传大文件？

- 原始数据可能几十 GB 甚至 TB 级，直接上传到业务数据库 / 对象存储：
  - 备份难、迁移难、成本高
  - 业务库性能差
  - 影响协作体验

### 一条 NAS 索引记录什么

| 字段 | 说明 |
| --- | --- |
| 索引标题 | 人类可读，例如"2024-Q1-细胞系测序原始数据"。 |
| NAS 路径 | 实际文件系统路径，如 `//nas-lab/project-001/raw-data/2024Q1/`。 |
| 负责人 / 维护者 | 谁负责权限申请、备份、迁移。 |
| 关联项目 | 可选，挂到 project_id 后在项目资料入口可直达。 |
| 数据描述 | 数据来源、采样、批次、大小、生成时间、格式。 |
| 访问权限要求 | 仅本项目 / 指定成员 / 需要书面申请（文本描述）。 |
| 备份情况 | 本地备份 / 异地备份 / 未备份（风险提示）。 |

### 如何使用索引

1. 在"资料与知识库 → NAS 资料索引"中新增一条，填入以上信息。
2. 如有需要，可在"项目资料"中上传一份小型 README，附上 NAS 索引链接，方便项目内成员导航。
3. AI 答疑场景下：若用户问起"原始数据在哪里"，AI 可以引用对应的 NAS 索引条目答复（前提是 NAS 索引有摘要 README 被写入 AI 知识库）。

## 资料与 AI 知识库的关系

```
公共资料 / 项目资料（原始文件）
      ↓  选择"同步到知识库"或手动添加
AI 知识库（ai.knowledge_document，含分块 + Embedding）
      ↓  用户问问题 → 语义检索 → 注入 RAG Prompt
AI 助手（回答 + 引用来源链接）
```

- **不是所有文件都需要进 AI 知识库**。
- 适合进知识库的：SOP、制度、流程、规范、FAQ、README 摘要。
- 不建议进知识库的：超大原始数据、未脱敏的个人信息、二进制可执行文件、图片/视频本身（可传一份文字摘要代替）。

## 常见问题（框架）

| 问题 | 建议答复 |
| --- | --- |
| 一个文件既有公共版又有项目特化版？ | 公共资料放"通用模板"，项目资料放"项目定制版"，在文件描述中标注区别。 |
| NAS 上的文件谁来备份？ | 由索引的"负责人 / 维护者"协调；建议按季度检查备份状态。 |
| NAS 路径变了怎么办？ | 更新对应的 NAS 索引条目，并在通知中告知受影响成员。 |
| 外部合作方想看资料？ | 使用文件外链（若启用）或将他们加入项目成员（注意合规）。 |
