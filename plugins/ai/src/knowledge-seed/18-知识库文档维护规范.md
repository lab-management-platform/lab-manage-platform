# 知识库文档维护规范（增删改）

## 谁可以维护

- 建议维护角色：`lab_admin`（业务侧）、`admin / super_admin`（平台侧）、`professor`（指导侧）。
- 普通角色（student、普通 member）默认只能**提问使用**、不能增删改；如发现文档需要补充，请联系上述维护角色。

## 维护入口

- AI 助手 → 对话工作台 → "知识库管理"（前端已提供"添加知识文档 / 上传知识文件 / 删除"的基础管理面板）。
- 也可由后端脚本批量导入（`plugins/ai/src/knowledge-seed` 的种子脚本就是典型的批量导入源）。

## 知识库文档的基本结构

| 字段                              | 必填     | 说明                                                                           |
| --------------------------------- | -------- | ------------------------------------------------------------------------------ |
| title（标题）                     | 是       | 简洁、清晰，用户一眼能知道主题。                                               |
| content（正文）                   | 是       | Markdown 文本。建议正文开头先用 2-3 句写"这段文档讲什么"，能显著提升检索质量。 |
| category（分类）                  | 建议     | 按"文档索引"的分类约定，便于过滤与前端展示。                                   |
| tags（标签）                      | 建议     | 2-5 个关键词，方便人工管理与检索兜底。                                         |
| sourceFileName / sourceMimeType   | 否       | 如果是从文件上传，则自动带文件名便于回溯。                                     |
| sourceImportMethod                | 否       | `manual`（手动写）或 `upload`（文件上传）。                                    |
| createdBy / createdAt / updatedAt | 系统自动 | 审计与维护责任追溯。                                                           |

## 一、新增文档（Create）

### 什么时候需要新增

- 实验室出台了新的 SOP、制度、流程、规范。
- 同事反复问同一个问题，AI 答复不到位。
- 公共资料 / 项目资料中某份文件"应该被 AI 引用"。

### 新增的质量要求

1. **一个文档一个主题**，不要一篇文档写"改密码 + 申请耗材 + 项目创建"三件事。
2. **标题要覆盖典型提问句式中会出现的关键词**，例如：
   - ✅ "忘记密码怎么办？重置密码流程"
   - ❌ "账户相关问题"
3. **内容建议结构化**：使用标题、列表、表格，不要只有大段文字。RAG 检索对结构化内容更友好。
4. **开头 2-3 句写摘要**：先明确告诉模型"本文档解答什么问题"，避免文档后面讲 A，前面全是无关背景，导致检索命中但回答偏。
5. **正文不要包含敏感信息**（身份证、银行卡、密钥、未脱敏手机号、个人隐私）。
6. **尽量用中文**，与用户提问的语言保持一致。

## 二、更新文档（Update）

### 什么时候需要更新

- SOP、流程、角色权限等**实际业务发生变更**时，第一时间更新知识库。
- AI 反复回答错误，经排查是知识库内容过时或不完整。
- 分类、标签需要调整（补充关键词、修正分类）。

### 更新的注意事项

1. **优先直接更新原文档**，而不是新建一个同名的。AI 召回时会根据最新内容生成 embedding。
2. 重要变更（例如流程从"2 级审批"改成"3 级审批"），建议在正文中保留"变更日期 + 变更点"的记录，便于答疑时告诉用户"生效时间"。
3. 若文档与公共资料 / 项目资料中的正式文件存在冲突，应以**公共资料中的正式文件为准**，并将知识库内容同步为最新版。

## 三、删除文档（Delete）

### 什么时候需要删除

- 相关制度 / SOP 已完全废弃，且不希望 AI 再引用。
- 文档内容存在明显错误，且无法通过"更新"修正。
- 重复 / 测试数据。

### 删除的注意事项

- 删除动作会进入操作审计（`action = ai.knowledge.deleted`），管理员可在管理中心 - 审计日志中看到谁删了什么、何时删。
- 建议删除前先确认：是否有人还在参考该文档？是否有新文档替代？删除后是否会导致相关问题 AI 回答质量下降？

## 四、文件上传到知识库（Upload）

当前支持作为知识库来源的文件类型（前端已实现）：

- 文本类：`.txt` / `.md` / `.markdown` / `.json` / `.csv` / `.yaml` / `.yml` / `.log`
- PDF：`.pdf`
- Word：`.docx`

### 上传后的处理流程（对维护者透明）

1. 前端提取文件中的纯文本内容。
2. 可选：与用户手写的"补充说明"合并。
3. 提交后端，写入 `knowledge_document` 一条记录。
4. 后端将正文切分为若干 chunk（分块），调用 embedding 模型生成向量，写入 `ai.knowledge_embedding`，用于语义检索。

## 五、如何判断"维护得好不好"

可用以下 4 个自检问题：

1. 对同事最常问的 10 个问题，AI 都能**命中正确文档**并引用吗？
2. 对不完整的提问（知识库没记载），AI 是否用了"未在知识库查找到相应操作，酌情采纳。"作为兜底？
3. 任何制度 / SOP 变更时，相关知识库文档是否在**3 个工作日内**同步更新？
4. 文档中是否不包含任何敏感信息（密码明文、个人隐私、密钥）？

## 常见问题（框架）

| 问题                                     | 建议答复                                                                                                |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 为什么我刚加了文档，AI 还是回答老内容？  | 可能是对话历史还残留了旧上下文；可尝试换个问法、或清空对话历史再提问。                                  |
| 文档太长，上传后会截断吗？               | 不会；但会分块（chunking）。建议长文档先做结构整理，提升检索质量。                                      |
| 可以批量导入吗？                         | 可以，使用种子导入脚本（`knowledge-seed` 目录配套的导入脚本）或管理侧批量工具，具体由运维或管理员执行。 |
| student 不能维护知识库，怎么提修改意见？ | 在"项目笔记"或通知中心联系维护角色，并附上文档 ID / 文档标题与修改建议，管理员统一修改。                |
