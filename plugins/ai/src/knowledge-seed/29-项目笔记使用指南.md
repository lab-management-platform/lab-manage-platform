# 29-项目笔记使用指南

> 模块：项目详情页 → 项目笔记工作区（ProjectNotesWorkspace）
> 适用角色：项目成员均可见；owner/leader/advisor 或拥有 project:write 权限者可写
> 功能入口：左侧「项目 ▣」→ 选中项目 → 在项目详情主面板「项目笔记」区块点击「进入笔记工作台」按钮

## 一、进入笔记工作台

1. 左侧「项目 ▣」→ 选中项目，进入项目详情页。
2. 在主面板可见「项目笔记」卡片：
   - 显示当前笔记数（N 篇笔记）
   - 显示「支持 `[[笔记名]]` 内部链接」能力提示
   - 列表预览最近 3 篇笔记（标题、作者徽标、更新时间、正文前 80 字摘要）
3. 点击蓝色大按钮「进入笔记工作台」即可打开全屏笔记工作区。
4. 提示：项目树工作区和笔记工作区**互斥显示**（同时只能打开一个）。点"进入笔记工作台"时若项目树工作区是打开状态会自动切换。

## 二、笔记类型（noteKind）

每篇笔记都有类型标签，创建时可选择，不同类型对应不同的徽标色与默认模板：

| noteKind 值     | 中文标签 | 徽标色      | 适用场景                         |
| --------------- | -------- | ----------- | -------------------------------- |
| project_note    | 项目笔记 | 蓝色active  | 通用日常记录：实验草稿、讨论记录 |
| meeting_minutes | 会议纪要 | 黄色pending | 组会记录、决议、待办清单         |
| report_draft    | 汇报草稿 | 灰色muted   | 为进度汇报预写的草稿材料         |
| knowledge_draft | 知识草稿 | 红色danger  | 准备沉淀进 AI 知识库的文档草稿   |

- 切换笔记类型不会丢正文，但会重新套用 FrontMatter（title、type、tags）。
- 系统预设默认类型是 project_note。

## 三、新建笔记

1. 在笔记工作台左侧笔记列表的顶部，点击「+ 新建笔记」按钮。
2. 弹出类型选择（或直接在类型下拉切换到你想要的 noteKind）。
3. 进入编辑器：
   - 标题栏可编辑
   - 正文是 Markdown 编辑器，左侧写 Markdown 原文，右侧是实时预览
   - 每篇笔记自动附带 FrontMatter（顶部 `---` 包裹的元信息），包括 title / type / aliases / tags

### 3.1 默认模板内容

```yaml
---
title: 未命名笔记
type: project_note
aliases:
  -
tags:
  - project
---
# 摘要

在这里写项目笔记正文。可使用：
- `#` 标题
- `-` 列表
- `**加粗**`
- `[[另一篇笔记]]` 内部链接
```

你可以直接把默认模板改掉，写你自己的标题、type、aliases、tags。

## 四、编辑 & 保存笔记

1. **选择笔记**：左侧列表点击任意笔记即进入编辑态（未保存的改动用橙色小圆点"dirty"标记提醒）。
2. **编辑器**：
   - 顶部可切换类型（noteKind）——改动后会同步写入 FrontMatter 的 type 字段
   - 左侧编辑，右侧实时预览 Markdown 渲染
   - 支持 `[[笔记名]]` 内部链接语法：渲染后会变成可点击链接（Obsidian 风格），点击可跳转到目标笔记
3. **保存**：点击编辑器右上角的「保存」按钮。
   - 保存成功会有短暂的 "Saved" 提示
   - 保存后「dirty」标识消失，列表中该笔记的"更新时间"同步刷新
4. **删除笔记**：编辑器右上角「删除」按钮。删除为**不可恢复操作**，请先确认没有用了再删。

## 五、笔记列表 & 过滤

1. 左栏笔记列表显示：
   - 笔记标题（加粗）
   - 类型徽标（颜色对应上面 4 类）
   - 作者名、更新时间
2. 顶部类型过滤器：
   - 全部 / 项目笔记 / 会议纪要 / 汇报草稿 / 知识草稿，五选一
   - 选中后列表只显示对应类型
3. 搜索：笔记列表内部支持按标题关键词过滤（如页面提供搜索框则直接输入关键词）

## 六、双向链接 & aliases（别名）

这是笔记系统最有用的特性之一：

1. **`[[笔记标题]]`**：在任何一篇笔记正文里写这种语法，渲染后：
   - 能跳转（点击）
   - 系统在两端自动计数"被哪些笔记引用了"（链路追踪）
2. **aliases 别名**：在 FrontMatter 里写
   ```yaml
   aliases:
     - 组会纪要0105
     - 周报
   ```
   之后别人写 `[[周报]]` 也能自动解析到这篇笔记，不用必须写全称。
3. **tags 标签**：FrontMatter 中 `tags:` 列表，可以被知识库检索 & AI 命中时作为命中依据之一。建议写成 `实验记录 / NLP / 2024Q1` 这种方便聚类的标签。

## 七、笔记写作建议

1. 实验记录建议单独写成 meeting_minutes 类型，标题带日期，比如「2024-01-05 实验失败排查记录」。
2. 准备把笔记贡献进 AI 知识库时，先改成 knowledge_draft 类型，正文检查后交给管理员或直接用 AI 知识库页面的"上传知识文档"功能导入。
3. 用 aliases 给长标题配一个短别名，之后在其他笔记里引用起来会轻松很多。
4. 不要把涉密 / 隐私内容写进笔记（当前版本所有项目成员都可见所有笔记，没有细粒度权限隔离）。
