# 部署方式与常用运维命令

## 架构与技术栈（简版）

- Monorepo：`pnpm workspace`。
- 前端：`apps/web`（React 19 + TypeScript + Vite 6）。
- 后端：`apps/api`（Fastify + TypeScript）。
- 数据库：PostgreSQL 16（业务）。
- 基础设施（Nginx / Postgres 配置）：`infra/` 目录。
- 业务插件：`plugins/*`（projects、inventory、collaboration、files、accounts、ai）。
- 核心包：`packages/*`（kernel、contracts、shared）。

## 本地快速启动（Docker Compose）

建议按仓库根 `README.md` 的步骤执行：

```powershell
Copy-Item .env.example .env
docker compose up --build -d
docker compose ps
```

默认地址：
- Web：`http://localhost:5173`
- API：`http://localhost:3000`
- API 健康检查：`http://localhost:3000/health`

## 本地开发（不依赖 Docker、只跑前后端）

前提：本地已运行 PostgreSQL，并在 `.env` 中正确填写 `DATABASE_URL`。

```powershell
# 1. 依赖安装
corepack pnpm run ci

# 2. 类型检查
corepack pnpm typecheck

# 3. 执行数据库迁移
docker compose exec api pnpm --filter @lab/api db:migrate
# 或本地：corepack pnpm --filter @lab/api db:migrate

# 4. 启动前端
corepack pnpm --filter @lab/web dev

# 5. 启动后端（另一个终端）
corepack pnpm --filter @lab/api dev
```

## 常用命令 / 排障

| 目标 | 命令（示例，Windows PowerShell） |
| --- | --- |
| 查看容器状态 | `docker compose ps` |
| 查看 Web 日志 | `docker compose logs -f web` |
| 查看 API 日志 | `docker compose logs -f api` |
| 构建前端产物 | `corepack pnpm --filter @lab/web build` |
| 类型检查整个 monorepo | `corepack pnpm typecheck` |
| 手动执行迁移 | `corepack pnpm --filter @lab/api db:migrate` |
| 重新构建并启动（修改 Dockerfile / compose 后） | `docker compose up --build -d` |
| 停止但保留数据 | `docker compose down` |
| 停止并清除 volume（会清数据库，慎用！） | `docker compose down -v` |

## 关键环境变量（与 AI 相关）

在 `.env` 中配置（示例，不代表一定完整）：

| 环境变量 | 作用 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 连接串，**业务库 + AI 知识库（ai schema）共用**。 |
| `AI_PROVIDER` | `ollama` 或 `openai`（与 OpenAI 兼容端点，含 DeepSeek）。 |
| `OPENAI_BASE_URL` | OpenAI 兼容基地址。DeepSeek 填 `https://api.deepseek.com`。 |
| `OPENAI_API_KEY` | API Key。 |
| `OPENAI_MODEL` | 聊天模型名，如 `deepseek-v4-flash`、`deepseek-v4-pro` 等。 |
| `EMBEDDING_PROVIDER` | `ollama` 或 `openai`。 |
| `EMBEDDING_MODEL` | 嵌入模型名（不同模型维度不同，知识库脚本会自动探测）。 |
| `EMBEDDING_BASE_URL` | 嵌入服务基地址。 |
| `EMBEDDING_API_KEY` | 嵌入服务 Key。 |

> 说明：知识库种子文档脚本（本文档同目录）运行时也依赖这些环境变量，尤其是 DATABASE_URL 与 Embedding 配置。

## 常见故障排查（框架级）

| 现象 | 检查点 |
| --- | --- |
| API 启动后立刻退出 | 检查 `DATABASE_URL` 是否可达；`.env` 是否加载到 API 进程 CWD；查看 `docker compose logs -f api`。 |
| 迁移失败 "字段 xxx 不存在" | 检查迁移文件顺序；查看 infra/postgres/migrations 最新 SQL 是否被执行。 |
| AI 回答空 / 报 Embedding 错误 | 确认 Embedding 服务可用（Ollama 本地 or OpenAI/DeepSeek 网络 + Key）。 |
| AI 只回答"不知道" | 先查看 `ai.knowledge_document` 中是否有文档；若已灌入，确认 embedding 是否正常写入 `ai.knowledge_embedding`。 |
| 前端登录后立即被踢（401） | 检查会话 token 校验、后端健康 `/health`、数据库是否可达。 |
| FAQ 模板不展示 | 检查 `ai.faq_template` 是否有数据；首次启动种子脚本会插入。 |

## 运维责任建议

- 日常版本发布、迁移执行：由平台管理员或研发负责人。
- 知识库内容维护：由 lab_admin 与教授共同负责。
- 敏感配置（Key、密码）：**不要提交到 Git**；通过 `.env.local` 或部署系统的 Secret 管理注入。

## 常见问题（框架）

| 问题 | 建议答复 |
| --- | --- |
| 我本地跑起来提示缺依赖？ | 先执行一次 `corepack pnpm run ci`，再按 README 启动。 |
| 切换 LLM / Embedding 提供方需要重启吗？ | 是的。后端启动时会读取环境变量来初始化 Provider；改完后重启 API。 |
| 需要完全重置数据库？ | Docker 场景：`docker compose down -v`，然后 `docker compose up --build -d`，执行迁移 + 种子脚本；注意这会清掉所有数据，仅开发环境允许。 |
| AI 知识库文档灌入后搜不到？ | 检查文档是否已写入 `ai.knowledge_document`，且对应的 embedding chunk 已写入 `ai.knowledge_embedding`；写入失败通常是 Embedding 服务不可用或维度不匹配。 |
