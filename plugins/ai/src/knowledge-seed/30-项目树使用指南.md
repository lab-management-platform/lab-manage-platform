# 30-项目树使用指南

> 模块：项目详情页 → 项目树工作区（ProjectTreeWorkspace）
> 适用角色：查看=所有项目成员；编辑=项目 owner / leader / advisor（canManageProject）
> 功能入口：左侧「项目 ▣」→ 选中项目 → 在详情的「项目树与进度」区块点击「打开项目树工作台」

## 一、进入项目树工作台

1. 左侧「项目 ▣」→ 顶部切换到目标项目。
2. 页面详情区找到「项目树与进度」环：显示节点总数、完成率环形进度条（done 绿色 / doing 蓝色 / todo 灰色占比）。
3. 点击按钮「打开项目树工作台」进入全屏项目树编辑工作区。
4. 提示：项目树工作区和笔记工作区互斥，打开时两者不会同时显示。

## 二、项目树核心概念

- **节点（TreeNode）**：项目拆解后的一个子目标。每个节点有名称、状态、责任人、备注、交付物说明。
- **父子关系**：节点之间可以有无限层级嵌套（项目 → 子课题 → 里程碑 → 子任务）。
- **根节点**：没有 parentId 的节点，是一个项目最顶端的目标。可以同时有多个根节点。
- **状态 status**：`todo（未开始，灰色）` / `doing（进行中，蓝色）` / `done（完成，绿色）`。
- **快照 Snapshot**：项目树在某个时间点的冻结版本（类似 Git commit），可以回溯查看。

## 三、节点操作

所有操作可以通过**右键节点**（或单击节点后右侧检查器面板）来触发。操作按钮包括：

| 操作           | 说明                                                                           |
| -------------- | ------------------------------------------------------------------------------ |
| + 添加子节点   | 在选中节点下新增一个子节点（缩进一层）                                         |
| + 添加兄弟节点 | 在选中节点后新增一个同级节点                                                   |
| 删除节点       | 把该节点及其所有后代都删除（高危操作，确认后才执行）                           |
| 展开 / 折叠    | 点节点左侧的 `− / +` 号：− 表示展开，+ 表示折叠，无儿子显示"·"                 |
| 拖拽移动       | 直接拖节点到另一个节点位置：上方插入 / 下方插入 / 作为子节点（三种 drop 模式） |

### 3.1 拖拽移动细节

1. 鼠标按住节点卡片拖动。
2. 拖拽到目标位置时，会显示三种 drop 高亮：
   - `drop-before`：在目标节点**之前**插入（兄弟）
   - `drop-after`：在目标节点**之后**插入（兄弟）
   - `drop-inside`：作为目标节点的**子节点**（新增一层嵌套）
3. 松手后位置立即生效。

## 四、检查器面板（Inspector，右侧）

选中一个节点后，右侧检查器面板中可以修改所有节点属性：

1. **名称**：节点标题（直接输入修改）。
2. **状态**（三个状态按钮 `todo / doing / done`）：
   - 当前状态的按钮会高亮对应颜色；
   - 点击即可切换；只有 canManageProject 为 true 时可编辑。
3. **责任人**：下拉从项目成员中选择，或者留空"未指定"。
4. **备注**（多行 textarea）：节点内部补充说明文字。
5. **交付物**（多行 textarea）：记录该节点完成时需交付的文档、代码、链接等。
6. 节点事实区（只读信息）：
   - 当前责任人姓名
   - 直接子节点个数
   - 后代节点总个数（含孙节点及更深）

## 五、工具栏操作（顶部 & 右侧）

顶部工具栏常见按钮：

| 按钮                      | 说明                                                                                                                                       |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 全部展开                  | 把所有 collapsed 的节点全部展开                                                                                                            |
| 全部折叠                  | 把所有有儿子的节点全部折叠为"…"                                                                                                            |
| 保存并生成快照 / 生成快照 | 把当前项目树结构保存为一个**快照版本**（Snapshot），写入历史；如果有尚未保存的改动（dirty），文案会显示"保存并生成快照"，保存+快照一次完成 |
| 丢弃改动                  | 当你有未保存修改时，点击可回退到上一次快照/原始结构                                                                                        |

"生成快照"按钮点击后会有短暂生成中态，完成后右上角弹出反馈：「已生成新的结构快照，右侧历史已更新。」

## 六、快照历史（右侧 Snapshot Section）

位置：检查器面板下方「快照历史」区块。

1. 列表展示所有历史快照：
   - 版本号（v1 / v2 …）
   - 创建者姓名 · 节点总数
   - 创建时间（精确到分钟）
2. 点击任一快照：
   - 该快照高亮为 "active" 蓝底
   - 下方出现快照详情卡片：完成率百分比、节点状态统计
   - **快照预览树**：只读方式查看当时的节点结构（不是直接回滚，防止误操作）
3. 如需真正**恢复到历史快照**：在预览区确认结构后，联系项目 owner 或实验室管理员，用"快照覆盖当前节点"接口恢复；演示 UI 当前未提供直接一键回滚按钮，防止误覆盖。

## 七、项目主面板里的项目树信息（不进工作区也能看）

不打开工作区时，项目详情主面板上有一个「项目结构预览」卡片：

- 显示总节点数、完成率环形进度条
- 显示 buildTreePreview() 生成的简要节点概览结构
- 点击项目名、节点状态徽标可以查看具体节点标题和状态

这对只需要快速查看进度，不需要调整结构的成员非常方便。

## 八、实用建议

1. **一级分解不要太细**：项目下的一级（根节点）建议按"里程碑 / 大模块"划分，每块再逐级拆。
2. **节点粒度**：做到一个节点可以被明确标记"完成"为止——如果一个节点始终既 todo 又 doing，通常是拆得太粗了。
3. **做进展 review 前先打快照**：每次组会 / 汇报前，生成一个快照做状态留档，回头对比会非常有价值。
4. **交付物字段要写上链接**：比如节点交付物里写「代码 PR #42」「报告文档 v1.doc」，之后点进去就能追溯。
5. **责任人在创建节点时就指定**：否则 todo 时没人认领，容易漏项。
