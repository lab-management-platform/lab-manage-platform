# 31-参会反馈操作指南

> 模块：会议与通知页 → 会议排期 → 参会反馈栏
> 适用角色：被列为会议参与人的项目成员（participantIds 包含你即可）
> 功能入口：左侧「会议与通知 ◌」→ 会议排期列表 → 找到你被邀请的那场会议 → 卡片下方"参会反馈"横条

## 一、查看会议排期

1. 左侧导航栏点击「会议与通知 ◌」。
2. 页面左侧是「会议排期」面板。按时间倒序展示所有会议（最新创建的排前）。
3. 每张会议卡片展示：
   - 会议主题（加粗） + 创建人姓名
   - 状态徽标：scheduled 已排期（蓝色 active） / completed 已完成（灰色 muted） / cancelled 取消（红色 danger）
   - 摘要（会议议程简介）
   - 所属项目（未指定会显示"项目：未指定"）
   - 开始时间（YYYY-MM-DD HH:mm，自动按当前时区显示）
   - 地点
4. 没有会议时显示 EmptyState「暂无会议 / 创建会议后，这里会展示预约、完成与取消状态。」

## 二、判断自己是否需要反馈

只有 `participantIds` 包含你的 userId 的那场会议，才会在卡片下方显示**参会反馈横条**（meeting-attendance-row）。不包含你 → 看不到反馈按钮，也不需要反馈。

## 三、三选一反馈：参加 / 请假 / 不参加

参会反馈横条由左至右：

1. **当前反馈状态 chip（只读）**：显示你对这场会议的最新反馈结果，初值为"待反馈"。
2. **「参加」按钮**（tertiary-button）
   - 点击：无需弹窗，直接保存。
   - 结果："当前反馈"变为「参加」；系统会通知会议创建人。
3. **「请假」按钮**（tertiary-button）
   - 点击会弹出 window.prompt 输入框，要求填写**请假原因**（必填，空字符串或纯空格不提交）。
   - 填写后确定："当前反馈"变为「请假」，原因会写入 attendance.reason 供创建人查看。
   - 取消弹窗：不提交反馈。
4. **「不参加」按钮**（tertiary-button）
   - 点击立即保存，无需额外输入。
   - 场景：时间冲突 / 课题不相关 / 有更紧急工作。
   - 但建议：能请假最好不要选"不参加"，请假会附带原因给创建人，便于他安排。

## 四、修改反馈（重选）

反馈按钮**不是一次性的**，在会议开始前你都可以反复点。比如：

- 一开始选了"参加"，后来发现赶不上 → 重新点「请假」补原因即可；
- 一开始选了"不参加"，老板让你必须参加 → 再点一次「参加」就能改回来。

每一次点击保存都会**覆写**你之前对同一场会议的反馈，不会留下多条冲突记录（同一会议对每个参会人只保留一行 attendance 记录）。

## 五、会议结束后的操作

1. 如果你有权限（`meeting:write` 或 lab_admin），在同一张会议卡片的下半部分会出现「会议纪要表单」：
   - 多行 textarea：默认 placeholder 「补充会议纪要、决议和待办事项」
   - 底部按钮「保存会议纪要并标记完成」
   - 点击后纪要保存到 meeting.summary 字段，并把 status 改成 completed
2. 如果你是普通参会人，看不到这个表单；但你的反馈记录会保留，供后续追溯。

## 六、反馈的作用

- 给会议创建人：自动统计参会 / 请假 / 不参加人数，便于调整场地、线上链接、时间等。
- 给 AI 助手 / 项目管理回顾：作为"该成员对该次会议的反馈记录"留存。
- 请假事由会被汇总进通知系统，以便实验室管理员 / 导师事后复盘。

## 七、小贴士

1. 反馈尽量及时：会议前 1~2 天就选，给创建人留够时间调场地 / 排议题。
2. 请假理由写清（比如"与某某课程时间冲突 / 身体不适 / 出差"），不要只写"有事"，方便别人理解。
3. 连续 3 次"不参加"同一项目例会：建议线下/私聊和导师/组长打个招呼，避免造成"长期缺席"观感。
4. 反馈按钮灰色不可点：通常是该会议已完成或已取消；此时反馈入口会被隐藏，如真的需要补说明请联系创建人在通知留言。
