# 28-任务评论使用指南

> 模块：项目详情页 → 任务看板 → 任务卡片
> 适用角色：所有已加入该项目的成员（owner / leader / member / advisor / observer 均可查看，owner/leader/assignee 可写评论）
> 功能入口：左侧「项目 ▣」→ 选中具体项目 → 「任务看板」区块 → 任务详情 / 评论入口

## 一、任务看板位置

1. 登录平台 → 左侧导航「项目 ▣」。
2. 顶部项目切换器选择目标项目，或点击项目卡片进入详情。
3. 向下滚动找到「任务看板」区块（ eyebrow=Tasks），位于"项目成员"与"进度汇报"之间。

## 二、创建任务

1. 任务看板顶部是「新增任务」表单，3 个字段：
   - **任务标题**：简短一句话描述要做的事
   - **优先级（priority）**：下拉 high / medium / low，默认 medium
   - **负责人（assignee）**：下拉列出当前项目所有成员，默认"待指派"（不指派）
2. 填写后点击「创建任务」按钮。
3. 成功后任务卡片出现在列表里，状态初始为 `todo（未开始）`。

任务卡片字段：

- 标题（加粗）
- 负责人行：负责人姓名 · 学号/工号（未指派显示"待指派"）
- 任务描述（创建时为默认描述）
- 状态徽标：todo / in_progress / done，颜色分别为灰色/蓝色/绿色

## 三、更新任务状态 & 标记完成

1. 每个任务卡片底部有「标记完成」按钮（条件显示）：
   - 你是项目 owner / leader / advisor（有 canManageProject 权限），**或**
   - 你是该任务的 assigneeId（负责人）
2. 状态是未开始/进行中时，按钮显示；任务已 done 时按钮隐藏。
3. 点击「标记完成」后：
   - 任务状态立刻变为 done，状态徽标变绿
   - 项目进度统计（顶部进度条）同步 +1 完成项

> **关于任务评论功能说明**：
> 当前版本（平台演示模式）的任务看板以"任务看板 + 状态流转"为主，**任务级评论入口与后端接口已在接口契约中预留（ProjectTaskComment 结构）但默认 UI 暂不展开评论**。
> 如你需要在某个任务下写讨论，推荐以下两种替代方式，均可被 AI 知识库检索：
>
> 1. 用「项目笔记」模块写一篇标题为"关于「XXX 任务」评审讨论"的笔记，正文里写评论内容，支持 `[[其他笔记]]` 链接互相引用。写笔记的步骤见《29-项目笔记使用指南》。
> 2. 在该任务的"任务描述"字段（description）追加评论备注，格式建议：
>
> ```
> [2024-01-15 张三] 复核通过，可以开始做。
> [2024-01-16 李四] 已提 PR，等待 code review。
> ```
>
> 下一版本会升级为正式的"任务评论区"功能（评论人、评论时间、@提及、标记已解决）。

## 四、为任务挑选负责人的建议

1. 学生项目：建议把 leader 能推动的任务先指派给 leader，细分后的任务再由 leader 按人分派。
2. 小任务（≤1天）不强制指派，看谁有空谁领取，但**不要出现任务长期无人认领**。
3. 优先级 high 的任务务必指派到人，否则容易拖慢项目。

## 五、常见操作问答

**Q：误把任务点成完成了怎么办？**
A：当前版本标记完成后没有 UI 回退按钮。请联系 owner/实验室管理员在后端数据库把 `status` 改回 doing/todo，或重新创建同名任务。

**Q：怎么删除任务？**
A：同"回退完成"逻辑——演示版未提供前端删除入口。如确实是误建，建议在标题前加「[废弃]」避免混淆；正式环境版本会补充删除/归档入口。

**Q：一个任务想挂多个负责人怎么办？**
A：目前字段只支持一位 assignee，建议把"统筹协调的那位"设为负责人，其余同事在描述里用「@ 姓名协作」列出。或拆成两个小任务分别指派。
