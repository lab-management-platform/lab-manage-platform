# 管理中心：成员、小组、角色模板

## 谁可以进入管理中心

- 系统角色：`lab_admin`、`admin`、`super_admin`。
- `professor` / `student` 在侧边栏默认不显示"管理中心"入口。

## 成员目录

### 能做什么

- 查看所有成员列表（支持按姓名、账号、角色、课题组关键词搜索）。
- 查看成员基本信息：账号、显示名、联系方式、所属课题组、系统角色、启用状态。
- 执行管理员操作（具体权限视角色等级而定）。

### 典型管理员动作

| 动作 | 说明 |
| --- | --- |
| 新增成员（注册本地账号） | 录入账号、显示名、初始密码、角色、所属小组。 |
| 重置用户密码 | 当用户忘记密码时，为其设置新的临时密码。 |
| 修改联系方式 | 帮用户更新手机号等。 |
| 调整系统角色 | student ⇄ professor / lab_admin / admin（注意权限收敛）。 |
| 停用 / 启用账号 | 离职 / 休假或异常账号停用，历史数据保留。 |

## 组织与小组

### 定位

"小组"对应实际的实验室 / 课题组（例如"干细胞组"、"算法组"、"平台公共支撑组"）。
成员归属到小组后，便于：
- 快速筛选成员（发通知、邀请会议、分配项目）。
- 权限与业务治理（lab_admin 仅管理某些小组的成员，若后续需要）。
- 统计（小组维度的项目数、物资消耗量等）。

### 建议操作

- 新成员加入时，必须指定所属小组。
- 小组改名不会影响成员与项目的关联数据。
- 小组删除前：确保成员与项目数据已迁移到其他小组。

## 角色模板

### 为什么需要模板

默认系统角色（student / professor / lab_admin / admin）和项目角色（owner/leader/member/advisor/observer）是**平台级通用定义**，但不同课题组可能对"leader 能做哪些具体事"、"advisor 能否修改项目资料"有不同要求。

"项目角色模板"用于：
- 预先定义好若干套"项目角色 → 具体权限"的组合（例如："A 课题组 leader 模板、B 课题组 leader 模板"）。
- 新建项目时直接选择一个模板应用，项目创建者不需要逐条点权限。

### 建议落地方式

- 首版可以先由管理员在文档 / 公共资料中维护"项目角色权限约定模板"。
- 待代码实现"可配置化项目角色权限"后，再落地为管理中心中的模板管理界面。

## 操作审计

> 管理中心中的所有敏感操作（新增成员、改密码、调整角色、停用账号、修改角色模板）都必须**可追溯**。
> 审计查询入口在管理中心的另一个 Tab，详见"管理中心：物资类别与审计日志"文档。

## 常见问题（框架）

| 问题 | 建议答复 |
| --- | --- |
| 能批量导入成员吗？ | 建议后续提供；首版可使用脚本（运维侧）批量创建，或管理侧一次一人新增。 |
| 删除成员会不会把他提交的资料也删了？ | 不建议物理删除成员；正确做法是"停用账号"，业务数据保留、审计可追溯。 |
| professor 能改管理员权限吗？ | 不能。角色调整必须由 admin / super_admin 执行，遵循"高 → 低"调整原则。 |
| 一个人可以在多个小组吗？ | 通常一个成员挂在一个主课题组；如确实需要多组身份，可在"其他参与课题"字段中登记（实现待定）。 |
