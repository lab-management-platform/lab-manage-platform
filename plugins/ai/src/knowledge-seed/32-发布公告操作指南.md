# 32-发布公告操作指南

> 模块：会议与通知页 → 发布公告面板（Announcement）
> 适用角色：**实验室管理员 lab_admin / 具有 meeting:write 权限的成员**（普通 member/student 看不到该面板）
> 功能入口：左侧「会议与通知 ◌」→ 页面右下半部分「发布公告」面板

## 一、谁能发布公告

两种条件满足其一即可：

- 你的系统角色是 `lab_admin`
- 你的权限列表包含 `meeting:write`

如果你**不具备任何一种**，页面右下半部分（创建会议 + 发布公告的双栏 split-layout）会整体不渲染。此时若想发布公告请联系管理员代发。

## 二、进入发布面板

1. 登录后左侧导航「会议与通知 ◌」。
2. 页面上方是「会议排期 / 通知收件箱」两列（所有可见）。
3. 页面下方是「创建会议 / 发布公告」两列（仅满足上面权限条件可见）。
4. 右下方卡片标题「发布公告」，eyebrow=Announcement。

## 三、发布公告三步

### 步骤 1：选择发送范围

最顶部字段「**发送范围**」下拉，选项分两类：

- `全部项目成员`：平台所有登录用户都能收到这条公告（全局通知）。适用于：服务器维护通知、实验室制度变化、公共假期、全室大会等。
- `当前项目 · <项目名>`：只让顶部项目切换器选中的那个项目的成员收到。适用于：某个课题组自己的提醒、单项目会议改时间通知、组内资料截止日等。

提示：切换顶部项目切换器，下拉中的"当前项目"名称会同步变。选项目范围前先确认顶部切换器的那个项目是不是你想要的那个。

### 步骤 2：填写标题

字段：**公告标题**。建议：

- 不超过 20 字，一眼能看完。
- 关键词放前面：比如「[服务器维护] 下周二凌晨 02:00-04:00 停机」，而不是「下周二凌晨要维护一下服务器大家注意哈」。
- 紧急、重要的可以在标题前加「[重要]」「[紧急]」前缀，收件箱一眼能看到。

### 步骤 3：填写公告内容

字段：**公告内容**（多行 textarea）。

- 说明这件事：谁 / 做什么 / 何时 / 何地 / 影响范围 / 联系方式。
- 多行内容不要堆砌一整段；用 `\n` 换行或 Markdown 列表样式排版。
- 涉及 URL、文档链接、会议 zoom 链接，务必直接贴出，不要让收件人再去别处找。

示例：

```
【时间】2024-01-09（周二）02:00 – 04:00
【影响】API 服务、AI 助手、文件上传均短暂不可用（最长 20 分钟）
【原因】数据库版本升级，修复 ai.knowledge_document 查询性能
【联系人】张工：138-0000-0000
```

### 步骤 4：点「发布公告」

右下角「发布公告」按钮（secondary-button）。点击后：

- 系统立即把该公告写入通知表（notifications，type=announcement）。
- 受影响范围的所有用户在「通知收件箱」面板会立刻看到新公告，未读数 `+1`，顶部铃铛图标也会显示红点。

## 四、发布后的行为

1. **谁会收到**：
   - 范围=全部项目 → 所有用户都能在收件箱看到。
   - 范围=某项目 → 仅该项目成员。
2. **展示格式**：
   - 标题、公告类型=公告、发布时间、内容
   - 新公告（未读）卡片会带 unread 边框加粗样式
   - 右侧有「标记已读」按钮
3. **标记已读**：
   - 读过后用户自己点「标记已读」，未读红点消失
   - 你作为发布人，也得自己点一次才会从"未读"变"已读"
4. **目前公告不可撤回编辑**：演示版本没有编辑/撤销入口。发布前再检查一遍标题、范围和内容。如果内容确实发错了，可以补发一条"【更正】原公告 xxx 修改为 yyyy"做澄清。

## 五、常见问题

**Q：公告范围选错（本该发 A 项目发成全部项目）能撤回吗？**
A：目前 UI 不支持撤回/删除。建议：① 补发一条更正公告，明确说明"此条只适用于 XX 项目，之前全室推送系误发，致歉"；② 如涉及敏感内容，联系后端管理员在 DB 删除对应 notification。

**Q：一条公告 500 字会不会太长？**
A：建议正文 ≤300 字。如果是长通知，请把核心要点放在开头，细节写"详情请点击 XXX 文档链接"——否则用户在通知收件箱摘要里看完 5~6 行就失去读下去的耐心了。

**Q：我是 professor 但发不了公告？**
A：professor 默认没有 `meeting:write`。如果课题组需要教授发通知，可让管理员在成员管理里把他升级为 lab_admin，或者直接请实验室管理员代发。

## 六、发布建议

1. 公告是"广播"，滥用会降低大家的重视度。非重要、非紧急的消息建议放到项目笔记 / 会议纪要里，不要每次都走公告通道。
2. 定期清理公告标题中的无意义前缀（不要每条都加重要，真的重要才加）。
3. 跨部门 / 跨项目的公告，优先选"全部项目"，不要分多个项目一条条发——这样管理员只需要核对一次内容，用户也不会收到重复通知。
