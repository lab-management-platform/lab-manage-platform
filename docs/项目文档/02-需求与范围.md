# 需求与范围

## 1. 用户角色

| 用户            | 核心需求                                                         |
| --------------- | ---------------------------------------------------------------- |
| 学生/普通成员   | 查看参与项目和个人任务，提交进展、资料和问题，申请物资，参加会议 |
| 项目负责人/组长 | 创建和分配任务，设置截止时间，查看组员提交，跟踪逾期和问题       |
| 教师/指导者     | 查看项目和成员全局，审核进展，点评成果，了解项目风险             |
| 实验室管理员    | 管理账号、物资、资料、知识库、会议和审批                         |
| 平台维护者      | 维护插件、权限、契约、部署和审计                                 |

## 2. 核心闭环

```text
创建项目 → 添加成员 → 拆解任务 → 分配任务 → 成员查看待办
→ 提交进展/资料/问题 → 负责人或教师点评/退回/确认
→ 物资申请与使用 → 会议沟通 → 项目结项与资料归档
```

## 3. 看板需求

### 学生看板

我的项目、我的任务、任务截止时间、近期进展、我的资料和笔记、我的会议、我的物资、器材归还提醒、快捷提交入口。

### 组长/项目负责人看板

本组成员和项目分布、任务完成率、组员待办、逾期任务、资料提交情况、待处理问题、物资申请和会议出勤。

### 教师/管理员看板

成员总数及年度变化、项目年度和等级分布、项目负责人及成员下钻、物资总库/在库/借出/逾期、设备分类、会议和项目进展。

看板必须支持多级下钻和横向交叉查询：成员 → 组别 → 项目 → 任务/成果/资料；项目 → 成员/进度/物资/会议；物资借用 → 借用人/项目/流水。卡片和筛选字段不能写死。

## 4. 项目需求

- 项目目录按年度、等级、归属、负责人、状态筛选。
- 项目基本信息包括项目名称、负责人、导师、成员、起止时间、状态、项目文档地址和项目仓库地址。
- `document_url` 指向项目说明、设计资料、在线文档或 NAS 目录。
- `repository_url` 指向 GitLab/GitHub 等代码仓库。
- 项目详情包括任务、项目树、进度汇报、项目笔记、资料、物资申请、会议纪要和教师点评。
- 项目负责人/组长分配任务；普通成员查看自己的任务并提交进展、资料和问题。

## 5. 物资需求

物资是上位概念，类别可配置，首版包括耗材和器材。

- 耗材：申请、审批、领用、库存扣减，领用后不归还。
- 器材：申请、审批、借出、应还、归还和逾期追踪。
- 其他物资：通过类别字段配置是否需要归还、计量方式和序列号要求。

## 6. 资料、会议和 AI

- 项目资料和公共知识库分开管理；文件可保存 NAS 路径或外链。
- 会议支持发布、参会确认、请假、纪要和项目关联。
- AI 支持知识库问答和项目上下文问答，模型地址和密钥由管理员配置。

## 7. P0/P1

P0：角色化看板、项目/任务/进度、项目地址字段、物资基础闭环、资料与知识库、会议通知、AI 基础问答、权限和审计。

P1：工资/经费、场地、存储柜、完整设备管理、NAS 双向同步、本地模型、Agent、对外宣传。
