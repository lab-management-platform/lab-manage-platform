# 角色与权限

## 1. 两层角色模型

系统角色决定平台级权限，项目角色决定项目内协作权限。两者组合使用，不能只靠一个全局角色解决所有场景。

### 系统角色

| 角色 | 说明 |
|---|---|
| `student` | 普通学生账号 |
| `professor` | 教师/指导者 |
| `lab_admin` | 实验室业务管理员 |
| `admin` / `super_admin` | 平台治理角色 |

### 项目角色

| 角色 | 能力 |
|---|---|
| `owner` | 项目负责人，推进项目、分配任务、管理项目资料 |
| `leader` | 组长/骨干，按授权协助负责人管理任务 |
| `member` | 普通成员，查看自己的任务并提交进展、资料和问题 |
| `advisor` | 教师/导师，指导、点评和审核 |
| `observer` | 只读观察 |

## 2. 权限矩阵

| 操作 | owner | leader | member | advisor | 管理员 |
|---|---:|---:|---:|---:|---:|
| 查看项目 | ✓ | ✓ | ✓ | ✓ | ✓ |
| 创建/分配任务 | ✓ | 计划支持 | × | × | ✓ |
| 更新自己的任务状态 | ✓ | ✓ | ✓ | × | ✓ |
| 提交进展/资料/问题 | ✓ | ✓ | ✓ | × | ✓ |
| 查看项目全部提交 | ✓ | ✓ | 受限 | ✓ | ✓ |
| 点评/退回/确认 | 计划支持 | 计划支持 | × | ✓ | ✓ |
| 修改项目基本信息 | ✓ | 计划支持 | × | ✓ | ✓ |
| 管理项目成员 | × | 计划支持 | × | ✓ | ✓ |

当前代码已实现 `owner/member` 数据角色和基础后端权限；`leader` 独立权限、负责人转让、问题处理和前端按钮差异列入 v1.0 联调。
