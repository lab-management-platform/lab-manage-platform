# 厦门大学统一身份认证接入

## 结论

厦门大学公开说明的新版统一身份认证采用标准 CAS 协议，不是 OIDC。平台已增加 CAS 登录适配器，和 Keycloak、本地账号并行存在；三种入口最终都进入同一套 `core.app_user`、业务角色和权限体系。

## 对接流程

1. 用户点击“使用厦门大学统一身份认证”。
2. 平台跳转到 `https://ids.xmu.edu.cn/authserver/login`。
3. 厦大认证成功后回调平台并携带 `ticket`。
4. API 调用 `serviceValidate` 获取学号或工号。
5. 平台按 `identity_provider=xmu-cas + identity_no` 或 `external_subject` 查找已审核成员。
6. 找到成员后创建平台会话；找不到或未审核时拒绝进入，不自动授予实验室权限。

## 申请材料

根据厦门大学信息与网络中心公开说明，需要申请应用并登记回调地址：

```text
https://lab.wuosu.xyz/api/auth/xmu/callback
```

申请通过后，再将 `XMU_CAS_ENABLED` 和前端构建参数改为 `true`。目前代码默认关闭，避免在没有校方授权时暴露入口。

## 配置项

```text
XMU_CAS_ENABLED=true
XMU_CAS_LOGIN_URL=https://ids.xmu.edu.cn/authserver/login
XMU_CAS_VALIDATE_URL=https://ids.xmu.edu.cn/authserver/serviceValidate
XMU_CAS_SERVICE_URL=https://lab.wuosu.xyz/api/auth/xmu/callback
XMU_CAS_FRONTEND_URL=https://lab.wuosu.xyz
```

前端镜像构建时同时设置：

```text
VITE_XMU_CAS_ENABLED=true
```

## 账号绑定规则

CAS 只证明用户是厦门大学统一认证用户，不自动决定实验室角色。管理员需要先在平台中创建或审核成员，并将其学号/工号填入 `identity_no`。首次 CAS 登录后，平台会把该账号的 `external_subject` 绑定为 `xmu-cas:<学号或工号>` 对应的身份。

## 安全边界

- 平台不接收、不保存厦大账号密码。
- CAS `ticket` 只在服务端向校方验证。
- 回调后的平台会话通过一次性短时交换码交给前端，不把长期会话令牌放在 URL 中。
- 未审核、停用或不存在的实验室成员不能登录业务系统。
- 生产环境应保持固定 HTTPS 回调地址，不使用动态 Host 拼接。
