# 技术架构

## 1. 总体架构

```text
React Web
  ├── 统一登录、导航、看板和项目上下文
  └── 插件页面、卡片和工作台
Fastify API Host
  ├── 认证、权限、审计、错误、事件和配置
  └── 插件装配、路由和数据库连接
Core
  ├── 插件契约
  ├── 权限与审计
  ├── EventBus
  └── 动态字段与看板注册
Plugins
  ├── projects
  ├── inventory
  ├── files
  ├── collaboration
  └── ai
PostgreSQL + Synology NAS Adapter + AI Provider Adapter
```

## 2. 边界原则

- `core` 不承载项目、物资等业务规则。
- 插件不直接导入其他插件源码。
- 跨模块关系使用稳定 ID、API、领域服务或 EventBus。
- 前端只调用统一 API，不直接访问数据库或外部组 API。
- 项目文档地址和项目仓库地址只保存导航元数据，不复制 NAS/GitLab 内容。
- 资料大文件优先保存于 Synology NAS；平台保存文件元数据、版本、权限和 NAS 路径/分享链接。
- Synology NAS 默认只在校园网或校园 VPN 中可访问，NAS 适配器必须把网络不可达作为可恢复的外部依赖错误处理，不得删除文件元数据。
- 动态字段、物资类别和看板卡片可扩展，但首版保持最小实现。

## 3. 跨组迁移

以本仓库为主干：SmartWrite-AI 的编辑器进入项目笔记/知识库，tech-material 的项目、任务、物资审批、会议和资料能力按插件拆解迁移。Spring Boot、MySQL、独立前端和外部 JWT 不作为生产依赖。

迁移顺序：身份权限 → 项目主轴 → 任务与进度 → 物资类别与审批 → 文件知识库 → 会议通知 → AI 增强。
