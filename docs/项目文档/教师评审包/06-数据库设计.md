# 数据库设计

## 1. 设计目标

数据库以项目为业务主轴，按 schema 划分边界；项目成员、任务、资料、物资、会议和 AI 通过项目 ID 关联。目标模型必须支持项目地址、动态字段、物资类别和器材归还，不把未来类别写死。

## 2. Schema

| Schema          | 主要表/职责                            |
| --------------- | -------------------------------------- |
| `core`          | 用户、会话、审计                       |
| `projects`      | 项目、成员、任务、项目树、笔记、汇报   |
| `inventory`     | 物资类别、物资、申请、审批、借还、流水 |
| `files`         | 文件、目录、版本、项目资料             |
| `collaboration` | 会议、通知、请假、纪要                 |
| `ai`            | 知识文档、对话、向量                   |

## 3. 核心表设计

### `projects.project`

`id`、`name`、`description`、`owner_user_id`、`advisor_user_id`、`document_url`、`repository_url`、`starts_at`、`ends_at`、`status`、`report_cycle_days`、`created_at`、`updated_at`。

`document_url` 指向项目文档、NAS 目录或在线文档；`repository_url` 指向 GitLab/GitHub 仓库。两者允许为空，使用 HTTP/HTTPS URL 校验，不替代文件版本表。

### `projects.project_member`

`project_id`、`user_id`、`member_role`、`identity_no`、`joined_at`。`member_role` 为 `owner / leader / member / advisor / observer`。

### `projects.task`

`project_id`、`assignee_id`、`creator_user_id`、`reviewer_user_id`、`title`、`description`、`status`、`priority`、`due_date`、`completed_at`。

### `inventory.material_category`

`id`、`code`、`name`、`return_required`、`quantity_mode`、`serial_required`、`dynamic_schema`、`active`。首版预置耗材（`return_required=false`）和器材（`return_required=true`）。

### `inventory.material`

`id`、`category_id`、`name`、`spec`、`stock`、`warn_stock`、`unit`、`location`、`manager_id`、`dynamic_attributes`。

### `inventory.application`

`id`、`material_id`、`applicant_id`、`project_id`、`quantity`、`reason`、`status`、`usage_mode`、`due_at`、`returned_at`、`reviewed_at`。`usage_mode` 为 `consume / borrow / return`；耗材不生成归还任务，器材必须生成归还任务。

### 其他表

`files.lab_file`/`file_version` 管理资料和版本；`collaboration.meeting`/`notification` 管理会议和通知；`ai.knowledge_document`/`chat_history` 管理知识库和问答。

## 4. 迁移注意

当前代码中的 `inventory.material` 仍是旧的物资基础表，目标模型需要增加类别表、`category_id`、归还规则和借还流水；当前 `projects.project` 需要增加 `document_url` 和 `repository_url`。正式实施前应新增 migration，不直接修改历史迁移文件。
