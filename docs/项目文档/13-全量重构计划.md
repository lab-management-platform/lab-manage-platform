# 全量重构计划

## 1. 目标

将平台重构为以工作台为入口、以项目为主线、以物资和资料为支撑的实验室业务平台。认证、权限、库存流水、文件版本和审计采用成熟模型，避免重新发明基础能力。

## 2. 总体决策

- 采用分阶段可运行的混合式重构。
- 认证接入 Keycloak/OIDC；业务系统不再保存或返回明文密码。
- 项目协作参考 OpenProject 的项目、模块、工作包、成员权限和看板模型。
- 文件资料参考 Nextcloud 的版本、共享和外部存储模型。
- 物资参考 ERPNext 的申请单、库存流水、仓库、序列号和借还模型。
- 平台继续实现实验室专属看板、项目上下文、物资规则和 AI 工具权限。

## 3. 阶段

1. 基线与安全清理：认证边界、密码迁移、统一错误、测试基线。
2. 身份认证：Keycloak Realm、OIDC、JWT/JWKS、角色和会话撤销。
3. 应用壳层：二级导航、路由、角色化工作台、项目上下文和响应式布局。
4. 项目域：项目目录、项目角色、任务、项目树、汇报、点评和项目地址。
5. 物资域：分类、物资、库存流水、耗材领用、器材借还和逾期。
6. 资料/会议/AI：NAS 元数据、文件版本、会议纪要、通知和受控 AI 工具。
7. 管理与看板：多级下钻、年度统计、组织、权限、动态卡片和审计。
8. 迁移上线：数据导入、灰度、回滚、旧接口下线。

## 4. 安全底线

- 生产环境不启用演示账号和本地种子账号。
- 不保存明文密码，不使用无盐 SHA-256 作为密码方案。
- 本地迁移期密码使用带随机盐的 scrypt/Argon2 格式；正式认证由 Keycloak 管理。
- API 只接受 OIDC JWT；迁移期本地认证必须显式开启且禁止生产环境启用。
- 找回密码只发送一次性重置流程，不在响应中返回新密码。

## 5. 验收

- 角色、项目角色和资源归属三层授权均有测试。
- 年度查询由数据库范围查询和索引完成。
- 耗材领用不产生归还记录；器材借出必须产生应还和逾期状态。
- 项目详情可跳转 `document_url` 和 `repository_url`。
- `format:check`、lint、typecheck、test、build 和主流程 Playwright 全部通过。
