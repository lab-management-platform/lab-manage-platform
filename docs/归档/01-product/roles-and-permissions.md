# 角色与权限说明

适用对象：产品、权限设计者、后端与前端开发  
更新时间：2026-07-01  
关联文档：[代码规范](../05-engineering/code-style.md)、[API 总览](../04-api/api-overview.md)

## 1. 系统角色

共享类型中当前定义了 6 级角色：

| 角色         | 标识          | 说明                                   |
| ------------ | ------------- | -------------------------------------- |
| 学生         | `student`     | 项目执行、资料上传、申请提交、AI 使用  |
| 教授         | `professor`   | 项目指导、项目维护、会议与审批相关操作 |
| 实验室管理员 | `lab_admin`   | 全局业务管理与主要运维角色             |
| 普通成员     | `member`      | 兼容型角色，当前业务上接近受限成员     |
| 平台管理员   | `admin`       | 平台治理角色，权限上接近全局管理员     |
| 超级管理员   | `super_admin` | 最高治理角色，主要用于平台级保留能力   |

## 2. 当前运行时边界

需要特别注意：

- 前端共享类型和权限映射已包含 6 级角色
- 认证与注册主流程目前仍主要围绕 `student / professor / lab_admin`
- 因此文档上要区分：
  - 共享角色体系：6 级
  - 当前业务主用角色：学生、教授、实验室管理员

## 5. 项目内成员角色

项目业务当前采用以下成员角色：

- `owner`：项目负责人，负责项目日常推进、任务分配和项目资料组织
- `leader`：组内骨干成员，可作为项目负责人下的协作管理角色
- `member`：普通组员，执行分配的任务、提交进度和资料
- `advisor`：导师
- `observer`：旁观/观察角色

当前项目模块和前端以这套角色为准。

## 6. 项目负责人和普通成员的实现状态

### 已实现

- 项目主表已有 `ownerUserId / ownerName / ownerIdentityNo`，能够记录项目负责人。
- `projects.project_member` 已有 `member_role`，支持 `owner / leader / member / advisor / observer`。
- 创建或修改项目时，负责人必须是带学号的学生账号。
- 添加普通成员时，接口不允许直接把成员设置为负责人；负责人需要通过项目主信息维护。
- 后端项目权限已区分：项目负责人和导师可以修改项目、项目树和任务；普通成员只能在授权范围内查看和更新自己的任务状态。

### 尚未完全实现

- `leader` 当前只是数据角色，尚未形成独立、完整的权限集合。
- 项目负责人转让、负责人离组、负责人替换时的校验和历史记录还需要补齐。
- 前端项目详情需要明确展示“项目负责人”和“普通成员”标签，并按角色显示可操作按钮。
- 看板需要分别展示“我负责的项目”和“我参与的项目”，不能只使用一个“我的项目”列表。

因此，当前结论是：**项目负责人和普通成员已经在数据模型及基础后端权限上分开；前端体验、负责人变更流程和 leader 独立权限仍属于计划完善项。**
