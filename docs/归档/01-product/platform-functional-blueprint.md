# 实验室管理平台功能蓝图

文档状态：v0.1，待老师和三位组长评审  
整理日期：2026-07-12  
目标版本：v1.0（2026-08-31）  
关联文档：[会议总结](../00-overview/meeting-2026-07-12-summary-and-actions.md) · [角色权限](./roles-and-permissions.md)

## 1. 产品定位

实验室管理平台是面向梦工厂人工智能社团内部成员的统一门户。它以“成员—项目—任务—资料—资源—会议”为主线，把 NAS、GitLab 等底层工具连接到一个面向用户的操作入口。

平台 v1.0 只优先解决内部管理和项目协作，不把对外宣传、正式统一认证和多实验室隔离作为首版前置条件。

## 2. 用户与视角

| 用户 | 主要目标 | 首屏重点 |
|---|---|---|
| 普通成员/学生 | 找到自己的项目、任务、资料并完成申请 | 我的项目、待办、会议、借用和逾期 |
| 组长 | 管理本组项目、成员、进度和申请 | 本组看板、任务、审批待办、成员状态 |
| 教师/指导者 | 了解全社全局并指导项目 | 成员、项目、资源、会议和进度统计 |
| 实验室管理员 | 维护账号、库存、知识库和平台数据 | 管理工作台、审批、库存、资料和审计 |
| 平台维护者 | 维护插件、契约、部署和运行稳定性 | 系统设置、插件状态、日志和发布信息 |

角色实现采用“系统角色 + 项目内角色 + 权限集合”组合，不把所有业务差异硬编码到单个角色名中。

## 4. 角色化看板

### 4.1 看板统一结构

所有看板由“卡片注册表”驱动。卡片至少包含：`id`、标题、适用权限、数据查询、刷新策略、下钻路由、空状态和错误状态。卡片可以由插件注册，宿主负责排序、权限过滤和布局保存。

### 4.2 学生/普通成员看板

- 我的项目：项目名称、角色、阶段、最近进展。
- 我的任务：待开始、进行中、逾期、已完成。
- 我的资料：最近上传、待补资料、项目笔记入口。
- 我的会议：近期会议、参会状态、请假入口。
- 我的借用：物品、借出时间、应还时间、状态。
- 逾期提醒：进入平台后优先展示需要归还的物品。
- 快捷操作：提交进度、上传资料、申请物资、请假。

### 4.3 组长看板

- 本组成员及项目分布。
- 项目阶段和任务完成率。
- 组员待办和逾期任务。
- 为组员创建和分配任务，设置负责人、截止时间、优先级和验收要求。
- 查看组员提交的任务进展、资料和问题，并进行跟进。
- 本组资料提交情况。
- 本组物资申请和审批状态。
- 本组会议出勤和请假情况。

### 4.4 教师/管理员看板

- 成员总览：按年度、分组、身份筛选，支持下钻到个人。
- 项目总览：按年度、项目等级、归属、进度筛选，支持下钻到项目。
- 物资（含耗材、器材等）：总量、在库、在用、高值、低值、逾期、存放位置和类别分布。
- 项目进展：近期更新、风险项目、待点评汇报。
- 会议情况：近期会议、参会/请假、历史纪要。
- 日常工作：资料提交、申请审批、任务完成等汇总。

### 4.5 看板下钻规则

示例：`成员总数 → 分组 → 成员 → 该成员参与的项目 → 项目详情 → 任务/资料/物资`。

下钻必须保留筛选上下文；返回上一级时不丢失筛选条件。统计卡片展示的数字必须能跳转到对应明细，不能只展示不可解释的数字。

### 4.6 多维度分析目录

教师或管理者进入全局看板后，一级目录至少包括：

- 成员情况
- 项目情况
- 设备情况
- 物资情况
- 经费/工资情况（是否纳入 v1.0 待确认）
- 日常工作/日常开展情况
- 会议情况

各一级目录都必须支持“列表 → 分组/分类 → 具体对象 → 关联业务详情”的层级浏览，并允许后续动态增加目录和字段。

成员情况的示例路径为：`成员情况 → 年度 → 组别 → 成员 → 所属项目 → 项目任务/成果/资料`。点击成员姓名时，至少能看到所属组、参与项目、承担任务、已提交进展和关联成果；年度统计至少支持 2024、2025、2026 等历史年度数据。

项目情况的示例路径为：`项目情况 → 年度 → 项目等级 → 项目归属/负责人 → 项目详情`。项目等级首版预置国家级、省级、校级、院级，同时保留可配置枚举能力。

物资和设备情况的示例路径为：`资源情况 → 总库 → 在库/在用/借出/逾期 → 分类或价值等级 → 具体物品 → 借用人/项目/流水`。设备支持高值、低值、类别、归属和存放位置等筛选。

会议情况的示例路径为：`会议情况 → 近期/历史 → 具体会议 → 参会人员/请假人员 → 会议纪要 → 关联项目进展`。

不同目录应支持横向交叉定位，例如从成员进入项目，也可以从项目进入成员；从项目进入物资申请，也可以从物资借用记录反查项目和成员。筛选项、排序项、分组项和统计口径不能写死在页面代码中，应由配置和稳定的字段定义驱动。

## 5. 项目管理

### 5.1 项目目录

支持“全部项目、年度、项目等级、项目归属、项目状态、负责人”等筛选。筛选器采用可配置字段，首版固定提供年度、等级、状态、负责人，后续允许管理员增加字段。

### 5.2 项目详情

项目详情至少包含：基本信息、项目文档地址、项目仓库地址、成员、项目树、任务进度、项目笔记、资料版本、结构化汇报、物资申请、会议纪要、教师点评/审核记录。

项目地址字段说明：

- `documentUrl`：项目文档、项目说明、设计资料、NAS 文档目录或在线文档地址。
- `repositoryUrl`：项目代码仓库地址，首版支持 GitLab/GitHub 等可访问链接。
- 两个字段只保存地址和展示名称，不把外部文档或代码复制到平台数据库；点击后在新页面打开，并根据用户在 NAS/GitLab 上的权限决定是否可访问。
- 地址为空时显示“未配置”，不影响项目其他功能；地址格式错误时前端提示，后端保存前也进行基础 URL 校验。

项目详情中的子区域以插件挂载点呈现，新模块不得要求重写项目详情主页面。

### 5.3 项目工作流

```text
创建项目 → 添加成员/导师 → 拆解项目树 → 分配任务
→ 组员查看待办 → 提交进展/资料/问题 → 教师点评或退回 → 阶段完成
→ 结项 → 资料归档到公共知识库（可选）
```

任务协作要求：

- 项目负责人/组长负责创建任务、分配组员、设置截止时间和验收要求。
- 普通组员只需要在个人工作台查看自己的任务，并更新进行中、已完成等状态。
- 组员可以提交进展说明、关联资料、阶段成果和需要帮助的问题。
- 教师/管理者在项目详情中查看所有成员提交内容，进行点评、退回、确认或继续跟踪。
- 项目负责人/组长可以看到本组任务完成率、逾期任务和未处理问题；教师/管理者可以看到跨组项目汇总。

## 6. 物资管理

物资是管理上位概念，具体类别通过配置扩展。首版至少包括：

- **耗材**：一次性或消耗性领用，领用后不要求归还。
- **器材**：可重复使用的借用物资，必须归还并接受逾期追踪。
- **可扩展类别**：管理员可增加类别，并配置该类别是否需要归还、是否计量、是否需要序列号和默认审批规则。

### 普通成员流程

查看可申请物资 → 选择物资类别 → 填写数量、用途和项目 → 提交申请 → 查看审批状态 →
耗材完成领用并结束；器材登记借出 → 查看借用记录 → 按期归还。

### 管理者流程

维护物资类别、目录和库存 → 审批申请 →
耗材登记领用并扣减库存；器材登记借出 → 跟踪借用人、位置和应还时间 → 逾期提醒 → 器材登记归还 → 库存流水。

物资属性采用“标准字段 + 动态字段”模式。标准字段包括名称、物资类别、数量、单位、库存状态、是否需要归还、位置、价值等级和归属；动态字段用于器材型号、序列号、采购批次、经费来源等差异化信息。

## 7. 文件资料与知识库

- 项目资料：跟随项目权限，支持文件、版本、标签、关联汇报和 NAS 外链。
- 公共知识库：面向全员查阅，管理员维护分类、内容和可见范围。
- 项目结项：允许把经过审核的项目资料复制或登记到知识库。
- 存储策略：v1.0 先支持平台记录元数据和 NAS 路径/外链；正式 NAS API 同步作为后续适配器。

## 8. 会议与通知

- 管理者创建会议，设置范围、时间、地点、议题和关联项目。
- 成员确认参会或提交请假。
- 会议结束后录入纪要，并关联项目、任务、资料或决策。
- 通知进入个人收件箱，并可在看板卡片中展示。

## 9. AI 助手

v1.0 目标是“可配置提供方 + 知识库问答 + 项目上下文问答”。API 地址、模型名、密钥和启用状态由管理员配置，密钥不能进入前端代码、Git 仓库或普通日志。云端和本地推理都通过统一 Provider 接口接入。

## 10. v1.0 验收标准

- 五类角色登录后看到不同且合理的看板。
- 学生可以完成“查看项目—提交进度—上传资料—申请物资—查看会议”的闭环。
- 管理者可以完成“查看全局—审批物资—追踪逾期—发布会议—维护知识库”的闭环。
- 项目详情可以看到成员、任务、资料、笔记和关联申请。
- 所有核心动作都有后端权限校验和基本审计记录。
- 关键路径有 Playwright smoke 覆盖，CI 通过后才能发布。
