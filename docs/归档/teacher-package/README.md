## 一、这份文档包回答什么问题

本包把三组合并会议中提出的要求整理成可评审、可执行、可验收的项目文档，重点回答：

1. 项目准备做什么，老师和不同角色能够看到什么。
2. 三组代码如何统一到一个项目、一个 API、一个数据库和一套权限体系。
3. 谁负责什么，怎样协作开发，何时完成什么，怎样判断 v1.0 可以上线。

## 三、当前明确结论

- 以实验室管理平台主仓库为统一主干，允许大重构。
- 统一前端入口、后端 API、PostgreSQL 数据库和权限体系。
- 采用微内核 + 插件化架构，项目、物资、文件、会议、AI 作为业务插件。
- v1.0 优先完成看板、项目、物资、资料/知识库、会议通知和 AI 基础能力。
- 目标上线时间为 2026-08-31。
- 文档发布到 NAS 的“实验平台管理”项目后，由常栋梁在群内通知相关成员查看。
- 每周开会一次，各组需要补充固定会议时间、会议链接和主持人。
- NAS 正式同步、工资/经费完整管理、设备/场地完整管理、对外宣传和本地模型属于待确认或后续范围。

## 四、需要老师确认的事项

- v1.0 是否严格限定为 P0 核心闭环。
- “工资/经费情况”是否纳入本项目，以及数据来源和可见范围。
- 设备、场地、存储柜首版做完整管理还是只做字段和看板预留。
- NAS 首版采用路径/外链登记，还是要求直接接入 NAS API。
- AI 首个模型提供方、预算、API 配置权限和本地模型计划。
- 2026-08-31 的部署设备、账号、数据和上线验收方式。

- 已实现：当前代码已有基础或可演示能力。

- 待确认：需要老师或组长做产品、权限、数据或资源决策。
