# 项目需求文档

适用对象：产品负责人、跨组整合方、实施与开发负责人  
更新时间：2026-07-12
关联文档：[功能设计](./functional-design.md)、[功能蓝图](./platform-functional-blueprint.md)、[会议总结](../00-overview/meeting-2026-07-12-summary-and-actions.md)、[项目总览](../00-overview/project-overview.md)

## 1. 目标

平台要把“项目”作为唯一主线，把协作能力集中到同一上下文里：

- 让项目负责人、导师、学生围绕同一项目工作
- 让物资、文件、汇报、会议与项目关联
- 让 AI 基于项目知识和实验室制度辅助成员工作
- 让后续不同技术组接入时，能围绕同一业务主线扩展而不是各做各的

## 2. 目标用户

- 学生：执行任务、提交进度、申请物资、上传资料、查看通知、使用 AI
- 教授：指导项目、查看进度、维护成员、安排会议、审批或监督业务
- 实验室管理员：全局管理账号、项目、审批、资料、知识库与协作流程
- 平台管理员 / 超级管理员：作为更高层治理角色存在于共享类型和权限体系中，用于未来平台化扩展

## 3. 核心业务主线

1. 建立项目并明确学生负责人、导师和组员
2. 通过项目树和任务定义阶段目标与执行拆解
3. 学生按项目提交资料、任务进度和结构化汇报
4. 物资申请、会议通知、文件归档都围绕项目流转
5. AI 根据实验室知识库和项目资料回答问题

## 4. 非目标

当前不是目标的内容：

- 多实验室多租户平台
- 正式 NAS 双向同步
- 正式统一身份认证接入
- 跨校或跨组织级别权限体系

## 5. 会议新增需求（2026-07-12）

以下内容来自老师、平台组和其他组长在三组合并会议中的共同讨论，作为当前需求基线。详细页面层级和交互规则见[功能蓝图](./platform-functional-blueprint.md)。

### 5.1 角色化看板

看板是不同角色进入平台后的首要入口，必须根据权限展示不同内容，并支持从总览逐级下钻到明细。

- 普通成员/学生：我的项目、任务进度、资料/笔记、近期会议、物资申请、借用记录和逾期提醒。
- 组长：本组成员、项目分布、任务完成情况、资料提交、物资申请和参会/请假情况。
- 教师/实验室管理员：全社成员、年度变化、项目总览、项目等级、设备物资、库存状态、逾期借用、会议和日常工作情况。
- 看板维度至少支持年度、分组、项目等级、项目状态、负责人等筛选；字段和卡片要保留动态扩展能力。
- 统计卡片必须能够进入对应列表和详情，不能只展示无法追溯的数据。
- 全局看板的一级分析目录至少包括成员情况、项目情况、设备情况、物资情况、经费/工资情况（是否纳入 v1.0 待确认）、日常工作/日常开展情况和会议情况。
- 成员下钻应支持“年度 → 组别 → 成员 → 所属项目 → 任务/成果/资料”；项目下钻应支持“年度 → 项目等级 → 项目归属/负责人 → 项目详情”。
- 成员、项目、物资、设备和会议之间支持横向交叉定位，例如从成员进入项目，也可以从项目反查成员和物资申请。
- 分组、年度、项目等级、设备价值等级等筛选条件采用可扩展字段，不将层级和统计维度写死在页面中。

### 5.2 项目管理

- 项目目录支持全部项目、年度、项目等级、项目归属、项目状态和负责人筛选。
- 项目负责人必须与普通成员分开建模和展示：负责人负责项目推进、任务组织和项目资料管理；普通成员负责执行任务、提交进度和资料。
- 项目看板分别提供“我负责的项目”和“我参与的项目”，项目详情明确展示负责人、组长、普通成员和导师。
- 项目基本信息新增“项目文档地址”和“项目仓库地址”两个字段：前者用于打开项目说明、设计文档、资料目录或 NAS 文档位置，后者用于打开 GitLab/GitHub 等代码仓库。
- 两个地址都应在项目详情、项目列表需要时和看板下钻结果中展示；访问权限仍由目标文档系统或代码仓库控制，平台不复制外部内容。
- 项目负责人/组长可以在项目内创建任务、指定组员、设置截止时间、优先级和验收要求，并跟踪任务状态。
- 普通组员可以在个人看板看到分配给自己的任务、截止时间、任务说明和当前状态，并提交完成情况、进展资料和需要帮助的问题。
- 教师/管理者可以在项目详情中查看成员提交的资料、进展和问题，进行点评、退回、确认或继续跟踪。
- 项目详情包含基本信息、成员/导师、项目树、任务进度、项目笔记、资料版本、结构化汇报、物资申请、会议纪要和教师点评/审核。
- 项目工作流为：创建项目 → 添加成员 → 拆解任务 → 分配任务 → 组员查看待办 → 提交进展/资料/问题 → 教师或管理者点评、退回或确认 → 阶段完成 → 结项归档。
- 项目详情的资料、笔记、物资和会议区域采用插件挂载方式，不能将所有功能写死在项目页面中。

### 5.3 物资管理

物资管理是原“耗材管理”的升级版上位模块。物资类别不写死，首版至少支持“耗材”和“器材”，后续可按需要增加设备配件、工具、试剂、办公物资等类别。

- **耗材**：领用后默认消耗，不要求归还；系统记录申请、审批、领用数量、用途、项目和库存扣减。
- **器材**：按借用管理，必须归还；系统记录借用人、借出时间、应还时间、归还时间、状态和逾期情况。
- **其他类别**：由类别配置决定是否需要归还，不能在页面代码中写死。

普通成员可以浏览可申请物资、提交用途和数量、查看审批状态；申请耗材时完成领用确认，申请器材时进入借用和归还流程。管理者可以维护物资类别、目录、库存、存放位置、审批申请、出库/领用、借用/归还和逾期追踪。

物资采用“标准字段 + 动态字段”模式。标准字段包括名称、物资类别、数量、单位、库存状态、是否需要归还、位置、价值等级和归属；型号、采购批次、经费来源等差异化信息通过动态字段扩展。

### 5.4 文件资料与知识库

- 项目资料与公共知识库分开管理，项目资料按项目权限控制，公共知识库面向全员查阅。
- 管理者可以维护培训资料、制度、学习资源和知识库分类。
- 项目资料支持版本记录、标签、关联汇报以及 NAS 路径或外链登记。
- v1.0 将 NAS 作为底层存储支撑，平台先完成门户和元数据管理；正式 NAS API 双向同步列为后续适配能力。
- 项目结项资料后续可沉淀到公共知识库。

### 5.5 会议与通知

- 支持会议发布、范围设置、参会确认、请假申请和个人通知收件箱。
- 支持录入会议纪要，并关联项目、任务、资料或决策。
- 近期会议和待处理通知应在看板中展示。
- 会议情况支持从近期/历史会议进入具体会议，再查看参会人员、请假人员、会议纪要和关联项目进展。

### 5.6 AI 助手

- 支持基于知识库的问答和基于项目资料上下文的问答。
- 管理者可以配置模型提供方、API 地址、模型名、密钥和启用状态。
- API 密钥不得写入前端代码、Git 仓库或普通日志。
- 通过统一 Provider 接口预留云端 API 与本地模型切换能力；首版至少保证一种可用提供方。

### 5.7 统一平台与跨组整合

- 三组最终使用唯一前端入口、唯一后端 API 和统一 PostgreSQL 数据库。
- 外部小组的代码作为能力和字段参考，重写到主仓库插件边界内，不保留独立 Spring Boot、MySQL、Next.js 或独立前端作为生产依赖。
- 所有模块必须遵循统一身份、权限、项目上下文、API、审计和事件规则。
- 新模块应以插件方式加入，插件之间通过契约和 EventBus 联动，不直接导入其他插件实现。

## 6. v1.0 范围与验收

### v1.0 必须完成

- 角色化看板。
- 项目目录、详情、任务/进度、资料和项目笔记。
- 物资目录、可配置类别、库存、申请、审批、耗材领用、器材借用/归还和逾期提醒。
- 项目资料、版本记录、公共知识库基础能力和 NAS 路径/外链登记。
- 会议发布、参会/请假、纪要和通知。
- AI 基础问答、知识库上下文和可配置模型提供方。
- 统一登录、权限校验和基础审计。

### v1.0 后续迭代

- 设备、场地、存储柜的完整资源管理。
- 正式 NAS API/SDK 双向同步。
- 本地模型推理和 Agent 工具编排。
- 对外宣传平台跳转。
- 多实验室、多租户和正式统一身份认证。

### 统一验收条件

- 学生能够完成“查看项目 → 提交进度 → 上传资料 → 申请物资 → 查看会议”的闭环。
- 管理者能够完成“查看全局 → 审批物资 → 追踪逾期 → 发布会议 → 维护知识库”的闭环。
- 关键页面根据角色展示不同内容，且后端接口同步进行权限校验。
- 核心统计可以下钻到列表和详情，项目、物资、资料、会议之间能够通过项目上下文关联。
- 关键路径通过 CI 和 Playwright smoke 检查后，才进入 2026-08-31 v1.0 发布候选。

## 7. 需求优先级与变更规则

- P0：影响 v1.0 核心闭环的功能，必须进入当前倒排计划。
- P1：对 v1.0 有价值但不影响核心闭环的增强功能，进入后续迭代池。
- 新需求必须补充用户、场景、验收条件、接口/数据影响、负责人和截止时间，再进入开发。
- 需求变化不直接口头覆盖原文，必须更新本文档或功能蓝图，并在周会记录变更原因。

## 8. 项目成员角色专项计划

当前 `owner / leader / member / advisor / observer` 已进入共享类型、数据库和项目插件；下一步在 v1.0 联调阶段完成：

1. 明确 `owner`、`leader`、`member` 的权限矩阵。
2. 增加项目负责人转让、替换和离组校验。
3. 完善项目详情和看板中的角色化展示。
4. 增加负责人、普通成员无权限和负责人变更的接口测试。
