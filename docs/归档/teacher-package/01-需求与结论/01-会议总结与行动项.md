## 1. 会议结论

### 1.1 统一主干

- 以 `lab-management-platform-migrate-temp` 为统一主仓库和唯一生产主干。
- 最终只有一个 Web 入口、一个 API 入口、一套 PostgreSQL 数据库。
- 三组原有项目作为能力来源、字段参考和迁移素材，不再并行作为生产入口。
- 允许对现有项目进行大重构；是否保留现有实现，以能否满足统一功能和架构为准。

### 1.2 统一技术路线

- 前端：React 19 + TypeScript + Vite。
- 后端：Fastify + TypeScript。
- 数据库：PostgreSQL。
- 工程：pnpm workspace Monorepo + Docker Compose。
- 架构：微内核 + 插件化；插件通过契约和事件通信，不直接依赖其他插件实现。
- 数据：统一身份、统一权限、统一项目上下文、统一 API 和统一审计。

### 1.3 各组能力吸收方向

| 来源 | 进入主干后的定位 | 处理方式 |
|---|---|---|
| 平台组 | 主干、内核、项目主轴和统一装配 | 继续建设并承担集成维护 |
| 林钰滔组 | 项目笔记、在线编辑、知识库资料能力 | 重写到主干架构，不保留 Spring Boot + MySQL 运行时 |
| 胡羿组 | 物资字段、审批、库存流程 | 吸收到 `inventory` 插件，不保留独立前端入口 |
| 两组 AI 能力 | AI 助手、知识库问答、模型适配 | 统一到 `ai` 插件，优先支持云端 API，预留本地模型切换 |

## 2. 老师明确提出的产品要求

1. **先把要做什么写清楚，再继续堆技术实现。** 功能要以 Markdown 文档分层表达，后续可以持续修改。
2. **入口优先做角色化看板。** 学生、组长、教师、管理员看到的看板内容不同。
3. **看板支持下钻和扩展。** 从全局统计进入分组、个人、项目和明细；筛选维度和字段不能写死。
4. **项目管理要有目录、筛选、详情、进度和点评。** 项目可按年度、等级、归属、进度等维度查看。
5. **耗材管理全面升级成物资管理，区分普通成员和管理者。** 物资是上位概念，首版至少包含耗材和器材，并允许后续增加类别；耗材领用后不需要归还，器材借用后必须归还。普通成员申请和查看记录，管理者审批、追踪库存、位置、借用人、归还和逾期情况。
6. **资料和知识库要有清晰边界。** NAS 是底层存储支撑，平台是面向用户的门户；公共知识库支持全员查阅和管理者维护。
7. **AI 配置不能写死在代码里。** 管理者应能配置 API 地址和密钥，并预留云端/本地推理切换能力。
8. **三组必须按统一 GitLab 流程协作。** `main` 由维护者保护，开发者使用功能分支，通过 Merge Request 审查后合并。
9. **目标是 2026-08-31 发布 v1.0。** 需要倒排每周任务，每周会议检查进度。

## 3. 会议中形成的产品范围

### P0：v1.0 必须可演示

- 角色化看板：个人项目、待办、会议、物资提醒和管理概览。
- 项目管理：项目目录、筛选、详情、成员、任务/进度、资料、项目笔记。
- 项目基本信息新增项目文档地址和项目仓库地址，方便从项目详情跳转到 NAS/在线文档和 GitLab/GitHub 仓库。
- 物资管理：可配置类别、目录、库存、申请、审批、耗材领用、器材借用/归还、逾期提醒。
- 文件资料：项目资料、公共资料、版本记录、NAS 路径/外链登记。
- 知识库：资料分类、上传、浏览、基础检索。
- 会议通知：会议发布、参会确认/请假、纪要和通知。
- AI 助手：基础问答、知识库上下文、可配置模型提供方。
- 统一登录、角色权限和审计基础能力。

### P1：v1.0 后继续增强

- 设备、场地、存储柜等资源管理。
- 成员年度历史和更丰富的管理统计。
- 项目结项资料一键沉淀到知识库。
- NAS 正式 API/SDK 双向同步。
- Agent 工具编排和本地模型推理。
- 对外宣传阵地跳转；会议中明确先完成内部管理，不把对外平台纳入 v1.0。

## 4. 当前实现与差距判断

### 已有基础

- 插件化 Monorepo、统一 Web/API 宿主和 PostgreSQL 基础。
- `projects`、`inventory`、`files`、`collaboration`、`ai` 插件骨架或基础实现。
- 项目树、项目笔记/编辑器迁移成果、物资申请审批、文件版本、会议通知、AI 知识库基础。
- 已有 API 收口矩阵和跨仓库字段映射矩阵。

### 需要收口

- 角色和权限需要统一到运行时、前端导航和接口校验。
- OpenAPI、共享类型和运行时接口需要逐项对齐。
- 看板需要从静态页面升级为可注册卡片和可配置筛选维度。
- 项目、物资、资料、会议、AI 之间需要通过统一项目上下文和事件联动。
- 动态字段需要先确定最小可用模型，避免各模块各自定义。
- 现有外部项目必须完成“能力映射—字段映射—接口映射—测试验收”，不能直接照搬运行时。
